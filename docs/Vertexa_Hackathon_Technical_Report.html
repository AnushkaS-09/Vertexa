1. Executive Project Overview

Vertexa (Civic-Task-Navigator) is an intelligent, dual-engine civic platform designed to demystify, structure, and navigate the complex, multi-departmental building permission and statutory clearance ecosystem across Maharashtra's Urban Local Bodies (ULBs).

In Indian municipal governance—specifically governed by the Maharashtra Regional and Town Planning (MRTP) Act, 1966 and the Unified Development Control and Promotion Regulations (UDCPR 2020)—securing permission to build a residential house, commercial office, school, or factory requires navigating up to 15 municipal departments, 25+ statutory certificates, and strict sequential gating milestones (such as IOD, CC, Plinth Verification, and OC).

The Vertexa Engineering Philosophy
Deterministic Mathematical Rules = Statutory Authority (100% legal accuracy, no AI hallucinations in legal conditions).
Google Gemini (gemini-3.5-flash-lite) = Plain-Language Assistance (Contextual breakdown of Marathi revenue terms and statutory bylaws).

Gemini AI Architecture & Model Benchmarking

In server/src/index.js, all AI interactions use generateWithGemini(ai, prompt, systemInstruction, timeoutMs = 18000) with multi-model failover:

  • Primary Model: gemini-3.5-flash-lite (Benchmarked at 933ms average latency, zero 429 quota exhaustion).
  • First Fallback: gemini-3.6-flash (Benchmarked at 3.3s–4.7s).
  • Second Fallback: gemini-3.5-flash.
  • Offline Fallback: If all network calls fail or time out after 18 seconds, the server seamlessly serves deterministic statutory seed graphs from server/src/data/seed_cases.json.
Honest AI Boundaries
Vertexa does NOT claim live web search grounding or real-time government crawling. AI is strictly constrained by prompt context and canonical node ID schemas to explain municipal regulations accurately without inventing bylaws.

5. Deterministic Rules & Regulatory Verification

Applicability Status Taxonomy

Status Meaning in Vertexa Example Statutory Scenario
APPLIES Legally mandatory clearance required by UDCPR 2020. Building height $\ge 15.0\text{m}$ mandates High-Rise CFO Fire NOC.
EXEMPT Project satisfies explicit statutory exemption criteria. Residential low-rise $< 15.0\text{m}$ is exempt from high-rise CFO NOC; 0 trees affected means tree felling NOC is exempt.
DOES_NOT_APPLY Condition is irrelevant to this location or typology. Eco-Sensitive Zone clearance in standard Pune/Mumbai municipal areas outside Matheran.
REQUIRES_VERIFICATION Automated determination is impossible without physical survey sheets or CCZM grid maps. Airport funnel height limits, Heritage precinct 100m buffer zones, High-Tension wire clearance (IE Rules 1956), Road width $< 6.0\text{m}$.

Rule Evaluation Logic (eligibilityEngine.js)

Core Codified Statutory Rules:

  1. AAI NOCAS Airport Funnel: `airportZone === true` → `APPLIES`; `airportZone === false` → `REQUIRES_VERIFICATION` (CCZM grid check mandatory).
  2. Heritage Conservation: `heritageZone === true` → `APPLIES`; `heritageZone === false` → `REQUIRES_VERIFICATION` (DP Sheet buffer check).
  3. High-Rise Fire Safety CFO NOC: `buildingHeight >= 15.0m` → `APPLIES`; `buildingHeight < 15.0m` → `EXEMPT`.
  4. Tree Authority Clearance: `treesAffected > 0` → `APPLIES`; `treesAffected === 0` → `EXEMPT`.
  5. Eco-Sensitive Zone (ESZ): `ecoSensitiveZone === true` or `jurisdiction === 'Matheran'` → `APPLIES`.
  6. High-Tension Power Line: `hasHighTensionLine === true` → `REQUIRES_VERIFICATION` (MSETCL clearance).
  7. Abutting Road Width: `roadWidth < 6.0m` → `REQUIRES_VERIFICATION` (Fire engine turning radius check).
  8. Typology Specific: Commercial (Parking), Institutional (RPWD Accessibility), Hospitality (Tourism/FSSAI), Mixed-Use (Segregation), Industrial (MPCB/DISH).

6. Roadmap State Machine & Security Architecture

Node State Machine & Sequential Locking

State Visual Indicator Prerequisite Condition User Capabilities
LOCKED Lock icon, dimmed opacity One or more incoming parent DAG nodes are NOT in `completedNodes`. Inspection allowed; "Mark as Done" action blocked with warning.
UNLOCKED Active blue/indigo border All incoming parent DAG nodes are in `completedNodes`. Full inspection, document downloading, "Mark Step as Completed" enabled.
SELECTED Glowing amber halo User clicked the node on the canvas. Displays node details in Document Drawer inspector tab.
COMPLETED Emerald checkmark, green border User explicitly clicked "Mark Step as Completed". Unlocks downstream child nodes; automatically advances active selection.

Security Architecture & Threat Countermeasures

Security Threat Implemented Defense Location in Code
API Key Exposure Server-Side Secrecy & Dotenv isolation. Never exposed to browser bundles. `server/.env`, `server/src/index.js`
Server-Side Request Forgery (SSRF) Strict domain allowlist (`*.gov.in`, `*.nic.in`, `*.aai.aero`) + DNS resolution blocking of private RFC 1918 subnets, loopbacks, and AWS metadata IPs (`169.254.x.x`). `server/src/utils/urlValidator.js`
Malformed Graph Injection DAG validator enforcing node types, valid stages, non-empty IDs, and self-loop rejection (`source !== target`). `server/src/utils/graphValidator.js`
AI Latency & 503 Outages Multi-model automatic fallback chain with 18-second timeout guard. `server/src/index.js`

Top 10 Technical Judge Questions & Answers

1. Why use deterministic rules instead of letting Gemini decide eligibility?
Municipal bylaws are legally binding statutory thresholds. LLMs can hallucinate numerical rules or invent non-existent exemptions. By codifying UDCPR 2020 rules mathematically, we guarantee 100% legal accuracy, using Gemini strictly for plain-language synthesis and explanation.
2. How do you prevent hallucinations in AI responses?
We pass the deterministic eligibility constraints and canonical node IDs directly into the Gemini system prompt, constrain output via JSON schema mode, and run a post-generation DAG validator (graphValidator.js).
3. What model are you using and why?
We use gemini-3.5-flash-lite as our primary model because it offers sub-second latency (~900ms) with zero quota failures, backed by an automatic failover to gemini-3.6-flash.
4. How does your SSRF protection work?
Our /api/link-status endpoint validates destination URLs against a strict .gov.in / .nic.in domain allowlist and performs DNS resolution to block private RFC 1918 subnets, loopbacks, and AWS metadata IPs (169.254.x.x).
5. What is the significance of REQUIRES_VERIFICATION?
Certain statutory determinations—such as Airport Funnel limits or Heritage precinct buffers—cannot be legally confirmed from a simple boolean. Marking them as REQUIRES_VERIFICATION provides honest civic transparency and instructs the citizen to verify survey sheets.
6. How does sequential node completion work?
In App.jsx, when a user clicks 'Mark as Done', the system checks the DAG edges to verify all parent prerequisite nodes are in completedNodes. If valid, it updates the state, syncs to localStorage, and advances selection to the next step.
7. What happens if the Gemini API goes down during a demo?
Vertexa has built-in offline resiliency. If the network or AI API fails, the backend and client seamlessly serve curated, validated statutory seed graphs from seed_cases.json.
8. What is an IOD (Intimation of Disapproval)?
In Mumbai and Maharashtra municipal law, an IOD is a conditional sanction issued under MRTP Act Section 45. It approves the architectural plan in principle but forbids physical construction until all departmental NOCs are cleared.
9. What is Plinth Checking?
Under UDCPR Reg 2.8.4, construction must halt when the foundation reaches plinth level so municipal engineers can verify on-site setbacks before granting permission for superstructure slabs.
10. Does Vertexa replace a licensed architect?
No. Vertexa is a civic navigation and transparency tool designed to empower citizens and architects, but official plan submissions under UDCPR Appendix B must still be signed by a COA-registered architect.
